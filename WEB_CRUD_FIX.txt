VAULTKEY APP - WEB CRUD FIX NOTES
==================================

STATUS: App running at http://localhost:8081 in a fresh browser window. Web-only CRUD failure fixed.

WHAT WAS WRONG
--------------
CRUD (add/edit/delete passwords) worked on Linux but not on Flutter Web.

Root causes found:

1. Flutter SDK was not installed on the machine.
2. flutter doctor could not detect Chrome/Chromium (only looks for google-chrome).
3. sqflite web worker binaries (web/sqflite_sw.js, web/sqlite3.wasm) were missing.
   -> Error: "failure to find worker javascript file at sqflite_sw.js"
4. getDatabasesPath() returns null (and throws) on web with sqflite_common_ffi_web.
   -> Error: "DatabaseException(getDatabasesPath is null)"
5. sqflite_common_ffi_web version 0.4.5 returns null for open() and SQL results on
   the current web SDK, making every INSERT/UPDATE/DELETE throw.
   -> Error: "Unsupported operation: unsupported result null (null)"
   (This is why CRUD worked on Linux but not web: Linux uses the native FFI path,
   web uses the old broken worker protocol.)
6. Cosmetic: RenderFlex overflowed by 8px in the home screen quick-action tiles.

HOW TO FIX / RUN IT YOURSELF
----------------------------
# 1. Install Flutter, then add /home/justin/flutter/bin to your PATH
flutter doctor                            # keep Chrome/Chromium green
export CHROME_EXECUTABLE=/usr/bin/chromium # if chromium is not auto-detected

# 2. Inside vaultkey_app/:
flutter pub get
# keep sqflite_common_ffi_web at ^1.2.0 (do NOT use 0.4.x) in pubspec.yaml
dart run sqflite_common_ffi_web:setup    # creates web/sqlite3.wasm + web/sqflite_sw.js
flutter run -d chrome --web-port=8081
# or build then serve:
#   flutter build web
#   (serve build/web/ with any static server, e.g. python3 -m http.server)

NOTES
-----
- On web the database persists in the browser's IndexedDB, keyed to the origin + port.
  Keep using port 8081 (or clear site data) or you get a "fresh" empty database.
- If you still see the old broken behavior in a browser tab that was opened before
  these fixes: CLOSE that tab fully (this terminates the stale sqflite shared worker),
  then reopen http://localhost:8081. Or just use the new window opened after the fixes.
